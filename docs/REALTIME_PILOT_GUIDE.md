# 实时语音助手／口译：E2–E5 操作与下一步

2026-10-24更新：真实TTS已在独立E5a接入，见[新指南](E5_LIVE_TTS_GUIDE.md)与[结果](../experiments/2026-10-24-e5-live-tts/RESULTS.md)。本页下文描述原57383固定音频原型，原页不变；E5a的CPU实时性能仍未通过，真人麦克风/ASR/翻译待验。

本轮2026-10-24按用户明确方向推进实时语音的视觉层。可运行原型使用同一个DSH ReplySpeaker播放分块PCM，再把真实调度时间、epoch、原采样率、源样本偏移和静音分析支路交给头像。ASR、翻译、对话和TTS仍归上游；本页面不调用这些服务。

## 当前可以操作

本机页面提供4条冻结输入，分别是已接受男女自然中文配音、另一句中文和另一句英文；后两条是E0开发集工程刺激，不代表人设配音质量。切换HeadAudio、RMS和静止口部三种模式，使用同一播放器。也可选择本地单声道PCM16WAV，按文件原采样率播放，仅在本机处理。

声音是唯一时钟。浏览器WebGL2绘制原静态头像及5种近似口型贴片，眼部独立眨眼；HeadAudio执行MFCC/分类，输出viseme权重。当前照片贴片用于调度、等待和恢复验证；口型切换、牙齿细节、眨眼贴片接缝和中文自然度仍需改善。英语合成语音训练的分类器不证明中文逐音素准确。

“播放开始调度”从按下播放开始，到播放器实际调用source.start并通知观察者；另加记录中的schedulingLeadMs，才得到计划音频起点相对请求的时间。它包含本机取素材/切角色开销，不是物理首声。首个非待机画面取rAF检查AudioContext.currentTime之时，与计划音频起点相减，包含原语音开头静音、检测窗口和平滑等因素；不是嘴形和每个音素的同步误差。frameIntervalP95Ms来自最近300次rAF回调窗口，可能跨相邻片段，不等于GPU执行耗时或实际显示帧率。explicitAvatarAudioHoldMs=0仅表示没有特意等头像再放声音；GPU资源争用/主线程卡顿仍须另测。

## 本地运行与复现

需要现有私有素材、头像项目质量环境的OpenCV/Pillow，以及相邻DSH插件已装好的esbuild。公开源码不包含音频、头像贴片、模型或vendor树。首次可显式下载官方固定hash依赖，全部放私有cache：

```bash
cd /path/to/projects/speech-avatar
.venv-quality/bin/python experiments/2026-10-24-e2-e5-realtime/prepare_preview.py --fetch-official
python3.12 -m http.server 57383 --bind 127.0.0.1 --directory outputs/realtime
```

当前端口被已有预览占用时直接使用已有页，或选空闲端口；不要关闭其他实验页面。12组工程对照将顺序完整播放4输入×3模式，通常约一分钟；导出JSON保存本机测量。人工质量字段保持null。源码在web/realtime，实际导入的speaker.mjs编译自相邻插件，未刷新任何运行中的DSH服务。

## 出错时如何恢复

| 情况 | 页面行为 | 恢复操作与边界 |
|---|---|---|
| 用户打断/换句 | 停止所有旧音源、取消reader、提升epoch，头像回待机 | 播放下一句；上一轮结果注入应拒绝，不重新发声 |
| 分块迟到 | 按实际安排的时间留出静音空隙，空隙期间回待机 | 新块到达后按实际start续播；不依据固定假定fps推嘴形 |
| 音频断流 | 播放已收到部分并明确标记音频不完整 | 下一轮新句恢复；真实TTS重试需上游请求ID/样本偏移，不能自动重播已说过的译文 |
| 口型模型加载失败 | 声音继续，口型降级RMS | “恢复口型模型”在新轮重新加载；原句不补播 |
| 画面准备迟到 | 静态头像过渡，视觉任务与音频准备并行 | 声音先开始；纹理就绪后恢复动画，已取消轮次不能回填 |
| WebGL上下文丢失 | 声音继续，显示闭嘴静态头像 | “恢复画面”；画面未恢复时也应允许播放新句 |
| 新请求覆盖旧完成回调 | 新epoch保留，新请求状态不被旧回调改成完成 | 用快速换句/打断检查；异步准备结束前也检查轮次 |

故障按钮只影响此页，不会操作远端模型或其他服务。生产应增加真实网络/设备/挂起恢复、20轮持续运行、内存与多浏览器覆盖。

## E5剩余工作与GPU

已增加可选播放器调度观察接口，默认无观察者时保持原音频路线，视觉观察者异常被隔离。当前仅验证实际类与本地PCM流的适配。下一步在隔离DSH实例中接入真实TTS流和可见开关，再接ASR/翻译/对话。先单用户、并发1，保留静态头像/纯音频降级，验证24kHz/短句/否定修正/插话和断线，不覆盖当前服务。

若需要E1的照片真实神经画质，另开有界CUDA实验，以MuseTalk任意新音频为第一基线，预处理缓存、模型常驻和流式输出分别测量。LivePortrait旧driver只能重放旧动作，需要另验新音频→表达控制；LongCat继续离线比较。GPU可加速模型，但不能单靠换GPU把旧driver变成可说任意句子的实时后端。

[GPU下一轮协议](../experiments/2026-10-24-e2-e5-realtime/GPU_PROTOCOL.md)列出资源门槛、独立进程、起止计时和拟定验收门槛。2026-10-24独立H100两卡都100%忙，本轮未分配CUDA；本机M4Pro WebGL2绘制已实测。完整实验、初轮缺陷及复测见[结果](../experiments/2026-10-24-e2-e5-realtime/RESULTS.md)。
